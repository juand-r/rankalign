# AmbigQA Task Notes

## Data Source

AmbigQA (Min et al., 2020) contains questions with multiple valid answers due to
ambiguity. We filter for questions where all annotators agree on ambiguity.

### Pipeline

1. **`scripts/extract_ambigqa_subsets.py`** -- Pulls from the HuggingFace AmbigQA
   dataset. Filters for questions with sufficient unique positive answers.
   Produces `data/ambigqa/train.jsonl` and `data/ambigqa/test.jsonl` (and `test2.jsonl`).

2. **`scripts/create_ambigqa_with_negatives.py`** -- Takes the extracted subsets and
   uses the OpenAI API (GPT-4o) to generate wrong answers via three negative
   strategies: `plausible`, `uninformed`, `clearly-wrong`. Also retains the original
   correct answers with strategy `ambigqa`. Writes to `data/ambigqa/with_negatives/`.

3. **`scripts/ambigqa_eda.py`** -- Exploratory data analysis.

  `plausibleqa_candidate`, `ambigqa_nq`, `ambigqa_qapair`, `gpt5`)

### v1 (current): Pure AmbigQA with generated negatives

- Directory: `data/ambigqa/with_negatives/`
- Task module: `src/tasks/ambigqa_v1.py`
- **Task names**: `ambigqa` (training), `ambigqa-<slug>` (per-question eval,
  e.g., `ambigqa-won`, `ambigqa-year`)
- Pure AmbigQA questions only -- no PlausibleQA contamination.
- Four balanced strategies: `ambigqa` (original correct), `plausible`, `uninformed`,
  `clearly-wrong` (3 negative strategies generated by GPT-4o).
- 3:1 negative-to-positive ratio.

## Current Thresholds (v1)

Decision: **min_train >= 10 positives, min_test >= 15 positives**.

The min_test >= 15 threshold was chosen because negatives had already been generated
for all questions with >= 15 positives (from both `test.jsonl` and `test2.jsonl`).
Lowering to min_test >= 10 would add 56 more test questions but would require
re-running GPT-4o to generate negatives for them.

## Task Registration (v1)

`src/tasks/ambigqa_v1.py` registers:

- **`ambigqa`**: Combined training task. Loads all of `train.csv` as train, empty
  test. Used for training models.
- **`ambigqa-<slug>`**: 17 per-question evaluation tasks (e.g., `ambigqa-won`,
  `ambigqa-year`). Each loads `train.csv` as train and the corresponding
  `<slug>.csv` as test. Used for evaluation.

### How tasks are loaded

1. `src/tasks/__init__.py` contains `from . import ambigqa_v1`. This import
   executes `ambigqa_v1.py` at module load time.
2. `ambigqa_v1.py` checks if `data/ambigqa/with_negatives/train.csv` exists.
   If yes, it calls `register_task()` for the `ambigqa` training task and then
   loops over all other `.csv` files in that directory, calling `register_task()`
   for each per-question task (`ambigqa-<slug>`).
3. Any script that does `import tasks` (e.g., `eval.py`, `eval_by_claude.py`,
   `ranking_loss_ref.py`) triggers all task registrations automatically.
4. The script then calls `get_task('ambigqa')` or `get_task('ambigqa-won')` from
   `task_registry.py`, which returns the registered task dict.
5. The task dict's `load_data()` function is called, which reads the CSV(s) and
   returns `(train_list, test_list)` where each item is a dict with keys:
   `question`, `answer`, `correct`, `strategy`.

### Item format

Each data item is a dict:
```
{'question': '...', 'answer': '...', 'correct': 'Yes'/'No', 'strategy': '...'}
```

The task's `make_prompt()`, `get_completion()`, and `get_label()` functions
convert these items into the format expected by the eval/training scripts.

### Script compatibility (verified)

All three main scripts work with the ambigqa v1 tasks:

- **`eval.py`**: Loads via `get_L_prompt()` which calls `task_config['load_data']()`.
  Uses `make_prompt()` for generator/discriminator prompts, `get_label()` for
  ground truth, `get_completion()` for CSV output. Works for both `ambigqa-<slug>`
  test tasks and the `ambigqa` training task (with `--train` flag).

- **`eval_by_claude.py`**: Same data loading path as `eval.py`. Self-typicality
  uses completions from `make_prompt()`. Fully compatible.

- **`ranking_loss_ref.py`**: Calls `task_config['load_data']()` directly. Filters
  positives via `get_label(i) == 'yes'` (1998 positives out of 7992 train items).
  Uses `make_prompt()` for prompt generation and `get_completion()` for target text
  in the full-completion scoring path. Fully compatible.
